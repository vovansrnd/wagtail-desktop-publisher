# wagtail-desktop-publisher

**Публикует Markdown-статьи и локальные изображения с компьютера на Wagtail через авторизованные API-запросы. Есть CLI и графический интерфейс; исходники Markdown остаются локальными, а неизменённый контент пропускается по хешам.**

## Основные возможности

- Создание и обновление черновиков или публикация страниц из Markdown и YAML frontmatter.
- Загрузка локальных изображений с повторным использованием идентичных по содержимому файлов.
- Хранение ID страниц Wagtail, состояния синхронизации и метаданных во frontmatter.
- CLI для скриптов/SSH и GUI для интерактивной работы.

## Требования и совместимость

- Заявленные зависимости: `requests >= 2.28; python-frontmatter >= 1.0; markdown >= 3.5; customtkinter >= 5.2`.
- Совместимость Python, Django и Wagtail нужно проверять совместно. Нижняя граница зависимости пакета не является подтверждением поддержки каждой версии.

Настольный клиент зависит от `requests`, `python-frontmatter`, `markdown` и `customtkinter`; он не требует установки Wagtail на самом компьютере издателя. Сервер должен поддерживать авторизованную запись через Wagtail API v3. Документация исходного пакета указывает Wagtail 7.0+ и проверку на 8.0; это не гарантия для всех будущих версий.

## Установка

Это настольный клиент/CLI. Обычно он запускается в отдельном окружении Python на компьютере редактора; добавлять его в `INSTALLED_APPS` серверного проекта не нужно. На сервере необходимо отдельно настроить совместимый API Wagtail и endpoint загрузки изображений.

```bash
pip install wagtail-desktop-publisher
```

## Первоначальная настройка

Минимальный пример для начала работы. Замените имена моделей, поля API и URL на соответствующие вашей конфигурации.

```bash
wagtail-publisher init --url https://example.com/api/v3 --token YOUR_TOKEN --site example.com
wagtail-publisher publish articles/2026/example/index.md --parent 42
# Добавьте --publish для немедленной публикации; сначала проверьте работу на черновике.
wagtail-publisher status articles/
```

Frontmatter обычно содержит `title`, постоянный `slug`, `excerpt`, `date` и при необходимости `year`, `tags` и ID рубрик. Поля страницы зависят от API-схемы вашей модели. Endpoint `/api/v3/publisher-images/` является пользовательским и отсутствует в стандартной установке Wagtail: зарегистрируйте его на сервере или настройте клиент на собственный безопасный endpoint.

### Важные замечания

API v3 и endpoint `/api/v3/publisher-images/` должны быть настроены на целевом сайте; endpoint загрузки изображений не входит автоматически в каждую установку Wagtail. Используйте отдельный токен с минимальными правами и проверьте массовую синхронизацию на копии статей.

## Безопасность и эксплуатация

- Поддерживайте зависимости в актуальном состоянии. Для пользовательского HTML используйте предусмотренную очистку и вывод; не применяйте безусловный `|safe` к сохранённым комментариям или сообщениям форума.
- Проверьте миграции и разрешения под обычной учётной записью, пользователем с ограниченными правами, модератором и администратором.
- В многосайтовой конфигурации проверьте каждый настроенный домен и неизвестный домен. Если Site не найден, запрос не должен расширяться до записей всех сайтов.
- Считайте API-токены, SMTP-пароли и приватные URL секретами. Не коммитьте их в Git и не вставляйте в публичные отчёты об ошибках.
- Сделайте резервные копии базы и медиа перед миграциями, массовым перемещением файлов, импортом или первой массовой публикацией. Сначала выполните операции на тестовом стенде.

## Рекомендуемые сочетания

- `wagtail-image-directories` — наиболее полезное дополнение для порядка `year/slug`, если endpoint загрузки использует эту модель.
- `wagtail-prose-editor-images` не требуется для Markdown-публикации.
